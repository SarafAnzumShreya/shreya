## Introduction

My 14-day attachment at BrainStation-23 Limited was one of the most valuable professional learning experiences I have had so far. It was not just a short training program — it was a realistic simulation of a software development cycle, where we were introduced to professional workflows, tools, and collaboration practices used in real projects.

The program began with company orientation and practical briefings about workflow, team structure, and expected development standards. We then moved into daily assignments, lab exercises, and mentoring sessions. The final stage focused on a group project that brought together many of the technical concepts we had been learning, from automation and data extraction to UI design and deployment.

What made the experience especially meaningful was the fact that we were not only learning fundamentals, but also applying them in a project under guidance. The environment felt close to a real software team setting, where discipline, communication, and iteration matter as much as technical skills.

---

## The Project: Web Scrapper

Together with two of my fellow classmates, I worked on a project titled **Web Scrapper: Streamlining Data for Innovation**. The goal was to build a multi-module web scraping application that could extract different kinds of data from the web and make them accessible in a structured and useful form.

The app was designed to support multiple data types, including:

- tables from websites
- images and media files
- movie details from IMDb
- video links from web pages
- news headlines from online sources
- eBay product details
- PDF links and downloadable files

We built the system as a hybrid platform that could be used through both a desktop GUI and a browser-based interface. This made it more user-friendly and showed us how real-world products often combine practical functionality with an intuitive interface.

The project was not limited to basic scraping alone. We were expected to think about how users would input URLs, choose data types, and retrieve clean results. We also built the application with the idea of storing processed data into a database, which made it more like a real production-ready solution rather than a simple demo.

## Tools and Technologies We Used

The project demanded a diverse technology stack. We explored several libraries and frameworks before finalizing the best approach based on experimentation and peer review.

### Core technologies

- Python for the application logic
- HTML and JavaScript for the frontend interface
- Flask as the backend framework
- Tailwind CSS for UI styling and layout
- BeautifulSoup for parsing HTML and static content
- Selenium for handling dynamic websites and browser automation
- Scrapy, Scrapy-Splash, and Scrapy-Playwright for advanced scraping workflows
- pdfplumber for reading and extracting data from PDF files
- MongoDB for persistent data storage
- GitHub for version control and collaboration

### Development approach

We followed an Agile methodology with short development cycles, testing, and improvements. This helped us stay organized and adapt quickly when a library or approach did not work as expected. It also taught us that software development is iterative — results are improved through testing, debugging, and review.

## Main Assignment and Objectives

Our main assignment was to build an integrated web scrapper application that could extract multiple types of online data through either a local GUI or a browser-based web interface. The platform was designed to automate the extraction process for diverse sources, such as:

- online libraries
- movie databases
- e-commerce websites
- PDF repositories
- news websites

The project was created to be modular and user-friendly. Users could input a target URL, choose the data type, and configure additional options such as API links for storage or extraction limits. This made the application not only technically advanced, but also practical for real usage.

### Project objectives

- design a modular and user-friendly scraping application
- compare several scraping libraries and choose the most efficient approach
- provide both GUI and web-based access for users
- automate extraction, formatting, and storage of scraped data
- deploy the working system online using Railway.app

These objectives reflected a real product mindset. It was not simply about learning a library; it was about building a complete solution that could be used, tested, and improved.

---

## Challenges We Faced

As expected, the project came with several technical challenges. Some websites used static HTML, while others required dynamic loading and browser-based interaction. This meant we had to decide when to use BeautifulSoup and when Selenium was necessary.

We also encountered issues such as:

- handling duplicate links
- filtering irrelevant data
- scraping media files without overwhelming the interface
- managing selection of the right parser for the target content
- integrating extracted data with storage in a clean and structured way

These challenges were valuable because they taught me that scraping is not just about collecting data — it is about understanding the structure of the source, handling edge cases, and building robust logic.
